WindowDeck 是面向 **ColorOS 17 / C17** 的实验性 LSPosed 多应用工作台。它复用系统实时任务嵌入能力，让最多五个应用以主窗和侧窗的形式同时显示：在主窗中操作，点击侧窗切换，按需要添加、替换或移出应用。

当前发布为 **0.4.8-beta.28**，包名 **`io.github.xitc.windowdeck`**。项目仍处于测试阶段，依赖 ColorOS 私有接口；它不是 vivo 原子工作台的官方移植。

## 功能

| 功能 | 使用方式 |
| --- | --- |
| 最多五个实时任务 | 一个主窗加最多四个侧窗；侧窗显示应用内容，点击后切到主窗操作 |
| 主侧窗切换 | 点击侧窗切换，长按打开管理菜单；重复选择已加入的应用会切换到已有任务 |
| 运行中管理 | 添加、替换、移出应用；侧窗支持滑动移出和短滑回弹 |
| 两种布局 | 左右排列或上下排列；手机横握时采用左右排列 |
| 桌面手势入口 | 在系统上滑分屏 / 浮窗面板中增加“添加到工作台” |
| 恢复与固定 | 从入口恢复已有组合；可固定一个应用，防止在工作台内被替换或移出 |
| 横屏应用展示 | 竖握时旋转显示横屏内容，横握时恢复正向；具体兼容性仍取决于应用 |

入口页可选择是否启用侧窗梯形，默认关闭。主窗保持矩形；侧窗用于预览和切换，不能直接操作其中的应用内容。

## 适配范围

**请先核对固件与桌面版本。系统同为 ColorOS 17，不代表接口和混淆符号一致。**

| 项目 | 当前适配基线 |
| --- | --- |
| 设备 | 一加 13，型号 `PJZ110` |
| 系统 | ColorOS 17 / Android 17 |
| 固件 | `PJZ110_17.0.0.100(SP01CN01)`，C17 / F.04 |
| 系统桌面 | `17.3.9`，versionCode `170030009` |
| Root / 框架 | KernelSU + LSPosed；模块使用传统 Xposed API 82 |
| 作用域 | 多窗口 `com.oplus.pscanvas`、系统桌面 `com.android.launcher` |

旧 C.93 / Android 16 基线不再适配。其他设备、OxygenOS、realme UI、其他 ROM 与 OTA 后的新版本未验证。APK 最低 API 为 35，仅表示安装门槛，不表示已支持 Android 15。

## 下载与安装

1. 从[本仓库 Releases](https://github.com/Xposed-Modules-Repo/io.github.xitc.windowdeck/releases)下载 APK。Beta 与每日版均为测试版本；[源码仓库 Releases](https://github.com/xitc/windowdeck/releases)也提供构建产物和校验文件。
2. 安装 APK，在 LSPosed 中启用“多窗工作台”。
3. 勾选 **多窗口** `com.oplus.pscanvas` 和 **系统桌面** `com.android.launcher`。本版不要求勾选系统框架 `android`。
4. 在 Root 管理器中给“多窗工作台”授予超级用户权限。
5. 首次启用或更新后，重新启动系统桌面与多窗口进程，使 Hook 重新加载。这会中断当前前台和工作台状态；先结束正在进行的操作。
6. 打开“多窗工作台”，选择应用并点击“用所选应用新建工作台”。

### 从旧包名迁移

beta.28 将包名从 `dev.windowdeck.app` 改为 `io.github.xitc.windowdeck`。**新版会独立安装，不能覆盖旧包名应用，配置也不会自动迁移。**

先在旧版退出工作台，并在 LSPosed 停用旧模块；再安装新版、重新授予 Root、启用模块并选择上述两个作用域，最后重启两个宿主进程。确认只启用一份 WindowDeck 模块。

相同新包名、相同发布签名的后续版本可以覆盖升级。本地自行签名的 APK 可能无法覆盖 GitHub 发布版。

## 日常使用

- **新建或恢复：**“用所选应用新建工作台”创建组合；“打开 / 恢复当前工作台”恢复已有组合。
- **切换：**点击侧窗，将其切到主窗；实际触控和输入在主窗中进行。
- **添加与替换：**点击侧边 `＋` 或菜单中的“替换应用”，回到桌面选择应用；也可从系统上滑面板选择“添加到工作台”。
- **管理：**长按侧窗或点击 `•••`，管理应用、调整布局、固定或退出。
- **返回：**系统返回先交给主应用处理键盘、弹窗和内部页面；根页面返回桌面并保留组合。

新建工作台会替换当前多窗口容器，不能与另一个原生多窗口容器同时使用。目前仅适配主用户，不支持工作资料或多用户。

## 常见问题

**启用后没有“添加到工作台”？**
先检查固件与桌面版本、两个作用域是否勾选，以及升级后是否已重启两个宿主进程。桌面只在进程启动时加载模块；接口校验不匹配时，相关 Hook 会跳过安装。

**可以安装到其他 OPPO / 一加机型吗？**
目前没有这些设备的兼容性验收。不要仅凭相同系统名称判断支持；反馈时请附完整固件和桌面版本。

**beta.28 已验证到什么程度？**
beta.28 基于公开 beta.27 做包名迁移，发布流程回归、布局回归、APK 构建、包名 / 版本检查及原发布证书校验通过。**新包名版本未做真机安装或行为验收。** beta.27 的有限真机结果只代表当时固件和已测应用；本地 dev.128 动画开发改动未包含在本版中。

## 已知限制

- 动画衔接、运行时方向变化、复杂输入法、多指、锁屏、进程死亡恢复和长期负载仍需进一步验证。
- 游戏验证不等于所有游戏实战通过；受保护内容与高负载恢复也需专项测试。
- 固定保护仅覆盖工作台内的替换、移出和滑动操作，不拦截应用内部启动其他应用。
- 系统根页面返回语义尚未完整复刻；上下布局的侧窗梯形变化较小。
- OTA 可能改变私有接口或桌面混淆符号，需要重新适配。

## 停用与反馈

停用前先从工作台菜单退出，然后在 LSPosed 关闭模块，重启 **系统桌面和多窗口两个进程**以卸载 Hook，再卸载应用并撤销 Root 授权。无需清除原应用数据。

请到[源码仓库 Issues](https://github.com/xitc/windowdeck/issues)反馈，附上模块版本、机型、完整固件、桌面版本、LSPosed / Root 方案，以及复现步骤。分享截图和日志前请移除账号、通知和其他个人信息。

源码、构建脚本与每日构建工作流位于 [xitc/windowdeck](https://github.com/xitc/windowdeck)。本仓库用于 LSPosed 模块介绍和 APK 分发。
